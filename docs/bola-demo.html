Apa Itu BOLA?
Broken Object Level Authorization — Penjelasan Simpel

💡 Analogi Gampang

Bayangkan loker di kantor. Lo punya kunci loker nomor 101. BOLA terjadi ketika satpam hanya mengecek "apakah lo karyawan?" tapi tidak mengecek "apakah loker itu MILIK lo?"

Akibatnya: Lo bisa buka loker 102 (punya orang lain) cukup dengan mengubah nomor. Di dunia API, "nomor loker" ini adalah parameter ID di URL.

✅

Akses Normal (Benar)

Operator BPS Jaksel login, akses data wilayahnya sendiri.

GET /api/wilayah/3174/penduduk

→ Server cek: JWT punya tenant_id=3174, URL minta 3174 → ✅ Cocok, data dikasih.

💀

Serangan BOLA (Ganti ID Aja!)

Operator Jaksel ganti angka di URL, coba akses data Jakpus.

GET /api/wilayah/3171/penduduk

→ Tanpa Zero Trust: Server cuma cek "JWT valid?" → Ya → Data Jakpus bocor! 😱

🛡️

Dengan Zero Trust (Solusi Kalian)

Middleware cek: JWT tenant_id (3174) ≠ URL tenant_id (3171).

HARD VIOLATION → Risk Score 50 → BLOCKED! HTTP 403
2
Kasus Nyata di Dunia
BOLA bukan teori — perusahaan besar pernah kena

🚗 Uber Eats

Ganti locationUUID di URL → bisa lihat revenue & analytics semua restoran di platform.

GET /v2/home/{UUID_LAIN}/analytics/sales

💰 Coinbase

Ganti asset_name di request body → bisa jual crypto milik orang lain.

POST /trade → asset: "BTC" (bukan miliknya)

☁️ Nextcloud

Ganti userId di URL → bisa baca jadwal cuti & data pribadi user lain.

GET /ooo/{USER_ID_LAIN}/status

🛒 E-Commerce (Riset)

Paper Muliono (2021) — BOLA di aplikasi e-commerce & e-banking Indonesia. Ganti order_id → lihat pesanan orang lain.

GET /orders/{ORDER_ID_ORANG_LAIN}
⚠️

Kenapa ini jadi #1 di OWASP? Karena serangannya sangat mudah (cuma ganti angka di URL), susah dideteksi scanner otomatis (butuh pemahaman relasi user-data), dan dampaknya masif (bocornya data bisa jutaan record sekaligus).

Perbandingan: Tanpa vs Dengan Proteksi
Kenapa RBAC saja TIDAK cukup
Aspek 🔓 Tanpa ZT (RBAC Saja) 🛡️ Dengan Zero Trust
Yang Dicek "Apakah JWT valid?" → Ya → Lewat JWT valid? + Tenant cocok? + IP wajar? + Waktu wajar? + Velocity normal?
Cross-Tenant Request ✅ DIIZINKAN (Data bocor!) ❌ DIBLOKIR (Score 50, Hard Violation)
IP Tidak Dikenal Tidak dicek sama sekali ⚠️ Soft Violation +20 (flagged, tetap allow)
Akses Jam 3 Pagi Tidak dicek sama sekali ⚠️ Soft Violation +10 (flagged, tetap allow)
100 Request/Menit Tidak dicek sama sekali ⚠️ Soft Violation +15 (flagged, tetap allow)
Semua Soft + Hard Tetap diizinkan 🤦 Score 50 → BLOCK + JWT Blacklist 🔒
Monitoring Tidak ada log khusus Real-time SOC Dashboard + Risk Score
💡

Desain Risk Score yang cerdas: Semua Soft Violation digabung = maks 45 (tetap < threshold 50). Artinya operator yang kebetulan pakai IP baru + kerja malam + request banyak tetap bisa akses. Yang diblokir HANYA Hard Violation (tenant mismatch = serangan BOLA).
